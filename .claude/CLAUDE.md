# FRCC Portal Form Renderer — Claude Code Instructions

## Project Overview
React application serving as a Power Pages replacement, rendering dynamic forms from JSON configuration generated by the FRCC Application Builder (C# → JSON → React pipeline). Configuration is stored in Dataverse and fetched via Power Pages Web API.

## Tech Stack
- React + TypeScript (Vite)
- MSW for local API mocking in dev
- Playwright for testing
- Power Pages / Dataverse Web API in production


## Key Conventions

### API Layer
- All entities use the generic `Entity = Record<string, any>` type — no entity-specific classes
- All queries use FetchXML
- Serialization via `serializeForApi()` — handles lookups (`@odata.bind`), dates (ISO string), nulls
- Custom `ApiError` class for error handling at API boundaries

### Form State
- `useFormState` hook centralizes values, dirty tracking, and field metadata
- Fields register on mount with `registerField(logicalName, metadata)`
- Child forms (TableEntry) each get their own `useFormState` instance

### Conditions
- Evaluated via `evaluateConditions(conditions, context)` in `src/services/conditions/evaluator.ts`
- Context: `{ formValues, currentValue }`
- Drive visibility, required state, and enabled state reactively

### Validation
- Entry point: `validateField(value, config)` in `src/services/validation/validators.ts`
- Individual validators: `validateRequired`, `validateRegex`, `validateMinMax`, `validateMinLength`, `validateMaxLength`

### Action Types
| Value | Name | Notes |
|-------|------|-------|
| 203300000 | FieldInput | Standard form field |
| 203300001 | FileUpload | Not yet implemented |
| 203300002 | TableEntry | Child table with CRUD + nested forms |
| 203300003 | PlainText | Static HTML content |
| 203300004 | QuickView | Read-only related entity view |

### Data Types (see `src/constants/enums.ts`)
SingleLineText, MultiLineText, Currency, WholeNumber, Decimal, Choice, YesNo, Lookup

## Development Mode
- `npm run dev` — starts Vite + MSW
- Add `?debug=true` to URL to load local config from `src/testing/formConfigs/formConfigv1.json`
- Production loads config from Dataverse via Power Pages Web API (`eyfrcc_version.eyfrcc_formcontent`)

## Adding New Things

**New Action Type:** Add interface in `types/config/Properties.ts` → update `ActionProperties` union → create renderer in `components/form/actions/` → update `StepActions.tsx`

**New Validator:** Add function in `services/validation/validators.ts` → call from `validateField()`

**New Condition Operator:** Add to `ConditionOperator` enum → implement in `services/conditions/operators.ts`

## Code Style Guidelines
- TypeScript for all new components
- Use `React.memo` to prevent unnecessary re-renders
- Hooks for state management — no Redux or external state libraries
- Keep components generic and configuration-driven
- Only validate at system boundaries (user input, external APIs)
- Avoid over-engineering — minimum complexity needed for the current task
